# 多设备部署(一主一从)

一台**主机**(跑调度、持真实数据、日常使用)+ 一台**开发机**(改架构/加功能/调试)。
代码走 git 双向,数据走快照单向(主→开发),schema 走 migrations 自动升级。

## 角色与同步通道
| 东西 | 方向 | 工具 |
|---|---|---|
| 代码 | 双向 | git(开发机 push → 主机 pull) |
| schema 变更 | 随代码走 | `backend/migrations.py`(开机幂等升级) |
| 真实数据 | 单向 主→开发 | `scripts/snapshot_for_dev.sh` |
| 密钥 `.env` / `backend/.env` | 各存一份 | 手动安全拷贝(勿进 git) |
| venv-quant / node_modules | 各自重建 | `requirements.txt` / `npm install` |

## 三条铁律
1. **真数据只能 主→开发 单向**;开发机的测试库**绝不推回主机**(会覆盖真实组合/模拟盘)。
2. **开发机不跑调度器**;只跑前端 + 后端 API 调试。避免误改数据、避免与主机重复执行。
   → 开发机的 `backend/.env` 里设 **`AFR_SCHEDULER_ENABLED=0`**(禁用调度器 + 开机补跑待办,
   只跑 API)。主机不设或设 1(默认开)。**全局只能有一台跑调度。**
3. **schema 改动走 `migrations.py`**(幂等),主机 `git pull` 后开机自动升级;**不手动改主机的库**。

## 角色对调(把现主机降级为开发机 / 换一台当主机)
数据所有权要交接,交接期间**只能有一台在跑调度**,顺序不能乱:
```
# —— 旧主机(现有真数据的这台)——
./launch.sh stop                       # 1. 停调度,冻结数据到干净点
pkill -f "launch.sh _keepalive"        #    停保活,防自动拉起
./scripts/snapshot_for_dev.sh          # 2. 导出一致性快照 ./snapshot/
# 3. 把 snapshot/ 的 db + .env/backend/.env 安全传给新主机

# —— 新主机 ——
# 4. clone 代码、建 venv/node、放密钥、导入数据(见"新开发机从零起步")
# 5. backend/.env 不设 AFR_SCHEDULER_ENABLED(默认开)→ 启动,它成为唯一调度方
./launch.sh daemon

# —— 旧主机(现在降为开发机)——
echo "AFR_SCHEDULER_ENABLED=0" >> backend/.env   # 6. 永久禁用本机调度
./launch.sh                                      #    只跑 API/前端做开发
```
交接后:新主机持有并推进真数据;旧机的数据成为"开发快照",需要新数据时反向从新主机拉快照。

## 新开发机:从零起步
```bash
# 1. 拉代码
git clone https://github.com/Hawisweary/stock-pilot.git
cd stock-pilot

# 2. 重建 Python 环境
python3.11 -m venv venv-quant
venv-quant/bin/pip install -r requirements.txt

# 3. 重建前端
cd frontend && npm install && cd ..

# 4. 放密钥(从主机安全拷来,勿走公开渠道)
#    .env  和  backend/.env

# 5. 放数据(主机跑 snapshot 后拷来,覆盖 data/ 下同名文件)
#    data/afr.db  data/us.db  data/cache.db
#    开发/改功能日常可只用小库 data/afr_pilot.db,要测全市场再拉完整 afr.db

# 6. 启动(开发机不跑调度,只调试)
./launch.sh            # 看需要;确认调度器开关/别入队真实调仓
```

## 主机:导出数据快照给开发机
```bash
./scripts/snapshot_for_dev.sh            # 一致性备份到 ./snapshot/(无需停调度)
# 然后把 snapshot/ 里的 db 传给开发机(rsync / 加密网盘 / U盘)
```

## 日常开发循环
```
开发机:改代码 → 用本地 DB 快照测试 → git commit && push
主机:  git pull → 重启(migrations 自动升级 schema)→ 新功能上线
```

## 常见问题
- **开发机要不要完整 6.3G 库?** 多数功能用小库(afr_pilot.db)即可;只有测"全市场评分/回测"才需完整 afr.db。
- **主机数据会不会被开发机搞坏?** 不会——只要守铁律 1(数据不回推)。代码通过 git 走、schema 通过 migrations 走,都不触碰主机数据内容。
- **两台能同时实时写同一份数据吗?** 本方案不行(SQLite 单文件)。真要双活需迁 Postgres(大改造,见讨论记录)。本方案是"两台都能用、数据不分裂"。
- **requirements.txt 在别的 OS 装不上?** 同 OS(都 macOS)最干净;跨 OS 个别 wheel 可能需手动调整。
