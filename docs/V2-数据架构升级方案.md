## 一、行情数据获取策略

### 1.1 自适应数据源选择

根据跟踪股票数量自动切换数据源：

```python
if len(stocks) <= 500:
    source = "tencent_http"    # 腾讯HTTP：最稳，不限频
elif len(stocks) <= 2000:
    source = "eastmoney_push2" # 东财Push2：支持批量更多
else:
    source = "akshare_spot"    # AKShare全市场盘口：一次5000只
```

| 数据源 | 适用规模 | 单次耗时 | 稳定性 |
|:-------|:--------:|:--------:|:------:|
| 腾讯 HTTP | ≤500 只 | ~50ms | ★★★★★ |
| 东财 Push2 | ≤2000 只 | ~100ms | ★★★★ |
| AKShare spot_em | 全市场 | ~3s | ★★★☆ |

### 1.2 数据获取分层

```
数据流架构:

     前端轮询(3s)
         ↓
   /api/realtime/quotes  ←── 内存缓存(3s) ←── 腾讯批量HTTP
         ↓
   PostgreSQL/Redis       ←── 每日收盘快照
         ↓
   技术面/基本面评分     ←── 因子引擎
```

- **盘中**：内存缓存 + 3秒TTL，不写DB
- **收盘**：每日 scheduler 触发批量写入 snapshot 表
- **评分**：基于 snapshot 计算，而非实时数据

## 二、K线数据全面批量改造

### 2.1 批量 K 线获取

```python
# 改造 tencent_adapter.py，增加批量函数
def fetch_kline_batch(codes: list[str], period: str = "daily") -> dict:
```

| K线类型 | 数据源 | 批量方式 | 当前 | 改造后 |
|:--------|:------|:---------|:---:|:-----:|

### 2.2 5分钟K线策略

```
              9:30                         15:00
              │                             │
  历史K线（DB）──── 开盘加载 ──── 5分钟K线（缓存）
                                    │
                              前端轮询(30s) 
                                    │
                              GET /api/realtime/kline/65?period=5min
                                    │
                              腾讯m5接口 → 当天缓存
```

- **当天缓存**：Redis/内存 `{stock_id}_5min`，TTL=30s
- **盘后清理**：当日K线写入 `stock_kline_5min` 表
- **前端**：日K线用已有组件，5分钟K线用相同K线组件（period参数切换）

### 2.3 分时图（异步获取）

```
股票详情页加载
    ↓
GET /api/realtime/intraday/{stock_id}
    ↓ (异步)
腾讯分时API → 返回今日全部分时数据
    ↓
前端画面积图（与K线图并列）
```

- **数据来源**：`http://ifzq.gtimg.cn/appstock/app/minute/query?code=sz000333`
- **返回格式**：每分钟一根 {time, price, volume}
- **展示位置**：详情页顶部，K线图右侧或上方
- **更新策略**：页面加载时取一次，不轮询（分时图形态固定）

## 三、东财 Push2 批量三合一

### 3.1 接口说明

```python
# 东财 Push2 批量 — 换手率 + 量比 + 内外盘 一次返回
POST https://push2.eastmoney.com/api/qt/ulist.np/get
Params:
  - secids: "1.000001,1.000002,...,1.600036" (54只)
  - fields: "f43,f44,f45,f47,f48,f162,f168,f772,f773"
    └─ f162=量比  f168=换手率  f772=内盘  f773=外盘

返回: {
    "data": [{
        "code": "000001",
        "f43": 14.25,    # 现价
        "f168": 2.34,    # 换手率%
        "f162": 1.15,    # 量比
        "f772": 123456,  # 内盘
        "f773": 98765,   # 外盘
    }, ...]
}
```

### 3.2 断连处理

```python
def fetch_push2_batch(secids: list, max_retry=3):
    for attempt in range(max_retry):
        try:
            resp = requests.post(URL, json={"secids": secids, "fields": FIELDS}, timeout=5)
            return parse_push2(resp.json())
        except (ConnectionResetError, requests.Timeout) as e:
            if attempt == max_retry - 1:
                raise
            time.sleep(0.5 * (attempt + 1))  # 0.5s → 1s → 1.5s
            continue
```

### 3.3 轮询策略

| 时间段 | 频率 | 操作 |
|:-------|:----:|:-----|
| 9:30-11:30 | 3s | 盘中最密轮询 |
| 13:00-15:00 | 3s | 同上 |
| 休市 | 停 | 不浪费 |

### 3.4 腾讯 vs 东财 双轨策略

```
推荐：只用东财Push2一路，一次拿到：
  量比 + 换手率 + 内外盘 + 现价/涨跌幅/成交量
  └── 替代腾讯行情轮询，减少一路请求
```

## 八、关键设计决策

### 决策1：腾讯还是东财？

**结论：只用东财 Push2 一路。**
- 东财一次返回：换手率 + 量比 + 内外盘 + 现价/涨跌幅/成交量
- 腾讯有的东财都有，不需要开两路
- 节省一路HTTP请求、简化前端轮询
- 断连用 `retry 3次 + 0.5s指数退避` 处理

### 决策2：5分钟K线存不存？

**结论：盘中不存，盘后写一次。**
- 盘中：内存缓存30s，纯转发
- 收盘（15:05）：统一写入 `stock_kline_5min` 表
- 历史5分钟K线保留 N 天（可配置）

### 决策3：分时图轮询吗？

**结论：不轮询。**
- 分时图是已发生交易的静态折线
- 用户打开详情页时取一次即可
- 实时价格变化用右上角数字显示，不重绘曲线
