### D7 · 数据库引入 ArcticDB(Man Group 时序 DataFrame 库)
- 决定:本次重构把数据库改为 ArcticDB
- **建议采用混合架构,不做全量替换**:ArcticDB 不支持事务、外键和多表 JOIN,不适合存业务状态
  - **迁到 ArcticDB(时序、大表、按日追加)**:日线行情(A 股/美股/ETF/指数/全球)、因子值、各维度评分历史、ML 预测、资金流/北向等按日序列
  - **留在 SQLite(业务状态、需要事务)**:组合、持仓、lots、待执行单、自选/分组、策略配置、任务队列、研报 FTS、调度状态
- 存储后端:本地 LMDB(单机,最简单);以后多设备同步可改 S3 兼容存储(如 MinIO)
- 收益点:列式压缩、按日期/列切片读取快;版本化(snapshot)方便回测复现;直接读写 DataFrame,省去 SQL 拼装;顺带缓解 afr.db 6.8GB 膨胀和 WAL 问题
- 风险:双库一致性(写入顺序、失败补偿);qlib/回测/因子引擎的数据读取层要统一改造;ArcticDB 对单条随机更新不友好(要改成按批追加)
- 前置:先建统一数据访问层(DAL),页面和服务不直接写 SQL;迁移按表分批进行,每批都和 SQLite 对账
- 关联:D3(因子计算全市场读数)、D1(美股量化数据规模)、qlib 半接(可以从 ArcticDB 导出 .bin)
- 状态:⏳ 未开始

### D8 · 业务库(留在 SQLite 部分)解决单写者问题
- 背景:D7 后 SQLite 只剩组合/持仓/待执行单/自选/配置/任务队列等小数据;剩余痛点是**单写者**和**不能跨机器共享**
- 方案(按成熟度,采用前两档):
  1. **统一连接工厂**:每个连接设 `busy_timeout`(如 5s)+ WAL;写事务一律 `BEGIN IMMEDIATE`(避免读锁升级写锁时直接 SQLITE_BUSY、不理会 timeout);事务内不调网络/LLM,保持短事务;禁止外层持有未提交写事务时再开新连接写(批量调仓 "database is locked" 的根因)
  2. **单写者队列**:所有写操作提交到后端唯一的写线程/服务串行执行(可基于现有 `job_queue` 扩展);多开连接不会提高单文件写吞吐
- 不采用(实验性,不适合支撑实盘决策):SQLite `BEGIN CONCURRENT` 分支(未合并主线)、Turso MVCC(beta/云端预览)、libSQL(无生产级并发写)
- 升级路径:真需要多机同时写时直接换 **PostgreSQL**,与 D7 共用统一数据访问层一起改
- 参考:sqlite.org begin-concurrent 文档;Turso 并发写博客;OneUptime "database is locked" 指南;SQLite 论坛
- 状态:⏳ 未开始

### D10 · LLM Agent 因子挖掘模块(新增,2026-11-09 决定加入)
> 参考:公众号"随机森林之外"《自动因子挖掘:如何让 Agent 从搜索走向新 Alpha?》(2026-11-02)及其引用论文(见文末"参考论文")。
> 核心原则:**生成候选因子很容易,难的是证明它为现有体系带来了经独立验证的新信息。** 多样化不是目的,持续增加有效信息才是。

**一、来自文章的设计要求**
1. **按信号去重,不按公式去重**:公式不同不等于信号不同(对动量取排名、取对数,股票排序完全一样)。候选因子必须和因子库比较**横截面排序相关性**,高相关的视为同一信号;再按信号家族聚类,统计"去重后的家族数"而不是"候选条数"
2. **防研究路径坍缩**:回测高分的方向会获得更多尝试,资源越来越集中到少数家族
   - 搜索预算在"深挖已有优势"和"探索新方向"之间显式分配(例如给每个家族设配额、保留固定比例的探索预算)
   - 搜索开始时先生成多个互补的研究方向(参考 QuantaAlpha 的多样化规划初始化)
   - 监控每轮各家族的占比,集中度过高时报警
3. **区分两种"集中"的原因**:统计偏差(早期高分有运气成分 → 加强独立验证)vs 市场状态变化(旧反馈已失效 → 反馈按时间衰减、按市场状态分组评估,可接现有 regime 模块)
4. **研究记忆要存完整信息**:不只存成功因子和分数,还要存研究假设、表达式/代码、**失败实验**、**在什么市场状态下有效**、适用边界。避免反复生成同类变体,也让后续研究能检验状态依赖是否稳定
5. **新颖性对照三个基准**:Agent 自己的因子库、现有因子体系(`factor_registry` 基础因子)、公开因子库(如 Alpha158 / Alpha360、学术文献因子)
6. **价值分两层评估,分开报告**:
   - 预测增量:加入已有预测模型后,样本外预测有没有改善(不是单看自身 IC)
   - 组合边际价值:在成本、换手、容量约束下,加入后组合表现有没有改善
7. **研究反馈和最终检验严格分开**:用来指导搜索的回测结果已经参与了筛选,**不能再作为证据**。因子、模型和搜索规则冻结后,用**从未参与筛选的时间段**做最终检验
8. **系统对比要公平**:和其他方法(现有 GP、随机搜索)比较时,数据起点、初始因子库、研究预算保持一致

**二、补充建议(文章之外)**
9. **安全执行 LLM 生成的代码**:不直接 `exec` 任意 Python。让 LLM 输出受控的表达式 DSL(算子白名单;表达式语言的统一口径见 D12 第一部分第 5 条);确需代码时放进沙箱(无网络、无文件写入、限时限内存)
10. **防未来信息泄露**:
    - LLM 训练语料里包含"哪些异象后来被证明有效"的事后知识,**模型知识截止日之前的样本外结果会偏乐观**;最终检验期应尽量放在模型知识截止日之后
    - Prompt 里不能出现检验期的任何数据或结论
    - 所有数据走 P5 清洗流水线(财务按公告日、停牌、涨跌停、新股、ST)
11. **多重检验校正**:试了几千条,总会有偶然高分的。总尝试次数记入试验账本(P12),用多重检验校正:Harvey-Liu-Zhu 建议的 t 值 > 3(t 值用 Newey-West 修正)、Benjamini-Hochberg 控制错误发现率;主判据用联合最大值 bootstrap(White Reality Check / Hansen SPA);**Deflated Sharpe 只作参考**(标签重叠时偏乐观,见 D16 第 2 条)
12. **数据切分**:训练(挖掘)/ 验证(筛选)/ 最终检验三段;最终检验段锁定,只在冻结后使用一次,使用记录留档
13. **评估指标统一**:IC / ICIR / Rank IC、衰减、换手、扣成本后的多空收益、分市场状态的 IC、对现有因子正交化后的残差 IC(衡量增量信息)、对复合因子的边际贡献
14. **审批门**:和 ML 预测一样,新因子经最终检验通过、人工确认后,才能进入正式因子库和模拟盘策略;不允许 Agent 直接改动生产因子库
15. **成本控制**:每次挖掘设 LLM 调用预算(DeepSeek token 上限)、相同 prompt 缓存、记录每条有效因子的平均成本
16. **复用现有组件**:表达式引擎 `factor_expression`、IC 引擎 `ic_engine`、中性化、现有 GP 挖掘(作为对照基准)、回测引擎、regime 模块
17. **可参考的开源实现**:微软 RD-Agent(基于 qlib 的因子/模型自动研发框架,和 qlib 半接方案契合);各论文代码以实际发布为准
18. **服务"学习"定位(D4)**:每个候选因子保留 LLM 给出的经济逻辑解释和失败原因,在因子实验室里可读,作为学习材料

**三、数据结构(初步)**

- 研究轨迹表:每轮的计划、生成、评估结果(含失败)、预算消耗

- 试验计数统一写入 P12 试验账本(与 D15、D17 共用)

**四(补)、来自 Jump Trading 分享的评估与工程要求**
> 参考:ICML 2026 Expo Talk《Multi-Agent System Design and Evaluation for Quantitative Finance》(Jump Trading,Loren Puchalla Fiore、Lucas Baker),公众号"多是别君词"2026-11-07 据现场记录整理。核心:**先回答"你怎么知道它做对了"**,评估要有时点、有轨迹、有成本约束,之后才谈多 agent。
19. **量化泄漏的验收方法**:同一套评估分别跑 LLM 知识截止日**之前**和**之后**两段,用两段结果的差距衡量泄漏程度;差距大的因子 / 方法不可信。比"检验期放在截止日之后"更具体,作为 D10 验收标准
20. **从最小循环起步**:第一版只做"单模型 + 一层工具 + 一条 agent 循环",和现有 GP 挖掘对比;**新增复杂度必须改善指标才保留**。投入顺序:直接提问 → 加 prompt 和上下文 → 设计工具 → 调整子 agent / 换模型 / 融合方式 → 后训练 → 微调。每往下一层先回答"针对什么目标专业化"
21. **先不上多智能体**:按任务结构选——依赖强的顺序任务用单 agent;可并行拆分的研究问题才用"主控 + 工作者";子 agent 要有明确角色
22. **轨迹指标与端到端指标并重**:除最终 IC / 收益外,每轮记录轨迹指标——是否用对数据、表达式能否运行、是否被去重淘汰、是否触发泄漏检查、调用了哪些工具。端到端分数会掩盖问题,轨迹指标定位问题(存入研究轨迹表)
23. **多指标评分表**:IC / ICIR、换手、拥挤度(D13)、扣成本后收益、与因子库相关性、容量等一起评估,在帕累托前沿上权衡;**不允许只优化单一指标**(防"目标指标很好、整体分析无效")
24. **三个系统指标**:性能、延迟(整条循环跑完到可行动的总时间)、成本;**记录每条有效因子的平均 token 成本**,成本高于预期价值的方案淘汰;注意便宜之后用量上升导致总支出增加
25. **灰盒约束**:外部规定输入、输出、阈值和约束——Agent 只能写候选因子表,不能修改生产因子库、数据、回测和评估代码,禁止刷指标;评分表由人定义
26. **状态完整性**:每次改动小而完整、可回退(像 Git 提交);只从可工作的状态推进到下一个可工作状态,出错时回退到上一个好状态,不在坏状态上继续
27. **自建评测集**:从自己研究中"来回纠正过"的案例积累考题,标注当时用了哪些数据、提问日期;保存每次运行的完整记录(输入、输出、对话、推理轨迹、不同模型对比)
28. **扩展会撞墙**:跑得更久、更多并行、更多算力都有上限,瓶颈通常是想法耗尽或缺乏多样性(与第 2 条防路径坍缩呼应)

**六、RD-Agent 在 Mac 上运行**

**八、论文方法与实施路线**(2026-11-10;AlphaAgent、FactorMiner、QuantaAlpha 读了全文方法部分,其余只读摘要)

*整体骨架*(AlphaAgent / QuantaAlpha / RD-Agent 共同):想法 agent(写假设)→ 因子 agent(翻译成表达式)→ 评估 agent(回测、查重、反馈)→ 研究记忆 → 下一轮。v1 可由同一模型轮流扮演三个角色。

*可直接采用的方法*
1. **结构化假设**(AlphaAgent):观察(当前市况或上轮结果)/ 知识(理论或经验规律)/ 论证(经济机制)/ 规格(参数,如"10 日高低点")。论证部分同时作为学习材料(D4)
2. **表达式中间层**(AlphaAgent、QuantaAlpha):LLM 只能用标准算子库组合表达式 → 解析成语法树 → 编译执行;编译失败由 LLM 修复但保持原意。用现有 `factor_expression`,按七类补齐算子(算术、统计、时序、截面、平滑、回归、逻辑;FactorMiner 有 60+ 个)。同时满足第 9 条安全要求
3. **语义一致性检查**(QuantaAlpha、AlphaAgent):LLM 检查员核对"假设 ↔ 描述 ↔ 表达式";不一致则重写,设最大重试次数
4. **复杂度惩罚**(AlphaAgent、QuantaAlpha):复杂度 = a₁×表达式长度 + a₂×自由参数个数 + a₃×log(1+所用字段数),纳入评分表或设硬上限
5. **语法树原创性**(AlphaAgent):与因子库及公开库(Alpha101 / Alpha158)计算最大公共同构子树;与截面排序相关性**互补使用**(前者看公式像不像,后者看信号像不像)
6. **五步准入流水线**(FactorMiner):① 部分股票上快速算 IC 初筛 → ② 与库内因子查相关性 → ③ 替换检查 → ④ 批内去重 → ⑤ 仅对幸存者全量验证
   - 论文 A 股默认:准入 **IC ≥ 0.04 且库内最大 |ρ| < 0.5**;替换 **IC ≥ 0.10、≥ 旧因子 IC 的 1.3 倍、且库内只有一个高相关因子**
   - ⚠️ 阈值基于 10 分钟级日内数据,日频需重新校准;项目统一的相关性准入阈值以 D15 第一部分第 3 条为准
   - **同一套准入 / 替换规则用于清理 P2 的 187 个"合成"因子**
7. **研究记忆:推荐方向 + 禁区**(FactorMiner):每批提炼为自然语言模板;记忆合并演化(如通过准入但相关 0.82 的变体重归禁区);按"当前库状况 + 最近被拒原因"检索,作为 prompt 约束;记录各逻辑领域**饱和度**(论文观察:库超过约 70 个因子后,高 IC 候选也频繁撞车)。失败**按失败模式分类**(AlphaAgent:假设不符、复杂度超限等)
8. **评估交给确定性工具**(FactorMiner):IC / ICIR 由代码计算,LLM 不自己算指标(防编造);调用现有 `ic_engine` 和回测引擎;按市场配置切换(方便 D1 美股)
9. **多样化初始方向**(QuantaAlpha、AlphaDiverse):从 Alpha158 中选约 20 个低相关因子作种子;初始假设在信号来源(价 / 量)、时间尺度(短 / 长)、机制类型(动量 / 均值回归 / 状态触发)上互补;每轮生成一组互补计划,轮间变换股票池或时间窗口
10. **轨迹变异与交叉**(QuantaAlpha):变异 = 自我反思定位最差的一步,冻结之前步骤,只重写该步及之后(可改时间尺度、加状态条件);交叉 = 组合多条高回报轨迹中持续贡献的片段
11. **多臂老虎机分配预算**(RD-Agent):每个家族 / 方向为一个臂,按历史收益与不确定性分配尝试次数(第 2 条的具体算法)
12. **从新闻 / 公告 / 研报自动找方向**(AlphaSeek):利用现有 35 万新闻、30 万公告和 P8 研报,是相对公开框架的差异化优势
13. **内部段反馈、外部段冻结检验**(AlphaDiverse):写入配置(同第 7、12 条)
14. **成本敏感性**(QuantaAlpha):基准成本用项目统一成本模型(P11),再测 1.5 倍、2 倍成本下的稳定性(论文用的是买入 0.05% / 卖出 0.15%,仅作参考)

*预算参考*(QuantaAlpha 附录,每次完整运行):AlphaAgent 约 150 万 token;QuantaAlpha 约 180 万(10 个并行方向 × 5 轮,约 20 小时,无需 GPU);RD-Agent 约 230 万。按 DeepSeek 价格估算单次成本

### D11 · 回测 / 数据管道:按层分工,研究层用 qlib,执行层用自研(✅ 已决定)
- 结论:不二选一。**研究层**(因子计算、ML 训练、批量回测、实验记录)用 qlib;**执行层**(模拟盘、待执行单、未来实盘)保留自研引擎;**数据唯一来源**是 ArcticDB,导出给 qlib
- qlib 的专业优势:`.bin` 列式数据读取快;表达式引擎 + Alpha158/360;`Recorder` 基于 MLflow 的实验记录(参数、模型、指标可复现);内置**时点数据库 PIT**(财务按公告日,`LocalPITProvider`);模型库;撮合层已有 A 股要素(`trade_unit=100`、`open_cost` / `close_cost` / `min_cost`、`impact_cost` 滑点、`deal_price` 可选开盘/收盘/VWAP)
- 自研引擎的不可替代之处:与模拟盘同一口径(T+1 次日开盘成交、手续费);与 V5 / 19 策略 / 待执行单直接打通
- **在 qlib 上改代码适配自有数据:可以(MIT 许可),但优先用扩展点,不改核心**:
  1. 自定义 `FeatureProvider` / `CalendarProvider` / `InstrumentProvider` 直接读 ArcticDB(省掉 dump_bin 中间文件,可选)
  2. 自定义 `DataHandler` / `Processor`:接入 P5 清洗规则(停牌、新股、ST、去极值、中性化)
  3. **分板块涨跌停**:`limit_threshold` 支持传入一对布尔表达式(买入受限 / 卖出受限),主板 10%、创业板 / 科创板 20%、北交所 30%、ST 5% 可**在数据里预先算好标记字段,无需改代码**;一字板识别同理
  4. 自定义 `Strategy`:把 19 个策略中需要的逻辑移植为 qlib 策略,用于研究回测
  5. 只有扩展点覆盖不了时才 fork:锁定版本、改动集中在少数文件、记录补丁清单,便于跟进上游
  6. 注意:RD-Agent 自带固定 commit 的 qlib(`rdagent4qlib` 环境),fork 版与它分开管理
- **一致性对账(必须)**:同一策略、同一数据,在 qlib 回测和自研引擎中各跑一次,对比成交和净值;差异须可解释(成交价、成本、涨跌停处理)才能用 qlib 的研究结论指导模拟盘
- 关联:qlib 半接方案、D7(ArcticDB)、P5(清洗流水线)、D10(因子挖掘复用 qlib 研究层)、P7(回测持久化可用 qlib Recorder)、P13(现有批量回测"数据只读一次"的改造并入这里)
- 状态:✅ **已决定(2026-11-10):研究层用 qlib**,执行层保留自研;改 qlib 时**优先用扩展接口**,接入方案见 D12

### D12 · 研究层接入 qlib 的方案(基于本机 qlib 0.9.7 核实的接口)

**一、总体原则**
1. **扩展接口优先,不改核心**:能用 `qlib.init` 注入、配置文件、子类继承解决的,不 fork
2. **qlib 只读不写**:qlib 只读取 ArcticDB 导出的数据或通过适配器读取,不写回业务库;研究结果经审批门后才进入正式因子库和模拟盘
3. **版本锁定**:`requirements.txt` 固定 `pyqlib==0.9.7`;升级前先跑一致性对账
4. **研究结论要能对账**:qlib 回测和自研引擎对同一策略的结果差异必须可解释(见 D11)
5. **表达式语言统一(✅ 已决定 2026-11-17)**:以 **qlib 表达式**作为研究层唯一的执行语言;在它前面加一层"类型 + 时间偏移(未来数据)"检查(D16 第 3 条),D10 挖因子、D15 体检、D17 文字转策略都输出这一种。自研 `factor_expression.py` 只维持现有功能,不再扩展算子;缺的算子用 qlib `custom_ops` 补(本表第 6 行)
6. **成本与交易规则**:qlib `Exchange` 参数、自研回测、模拟盘统一从 P11 的配置读取

**二、可接入的扩展点:接什么、怎么接、注意什么**

| # | 扩展点(qlib 0.9.7) | 接入项目的什么 | 怎么接 | 注意 |
|---|---|---|---|---|
| 1 | `provider_uri` + `dump_bin.py` | 行情、复权因子、基础字段 | ArcticDB → 按股票导出 CSV → `dump_bin.py dump_all` 生成 `.bin`;每日盘后 `dump_update` 增量 | **`dump_bin.py` 不在 pip 包里**,从 qlib 仓库 `scripts/` 取,版本对应 v0.9.7;代码要转成 qlib 格式(如 `SH600519`);停牌日不要用前值填充 |

| 3 | `feature_provider`(自定义) | 直接读 ArcticDB,省掉 `.bin` 中间文件 | 继承 `FeatureProvider`,实现 `feature()`;`qlib.init(feature_provider=...)` 注入 | **后期可选**;先用方案 1 跑通。自定义读取会绕过 qlib 的磁盘缓存,注意性能 |

**三、加入 qlib 的步骤**
1. **前置**:P1(10 年日线 + 日历)、P5(清洗规则定义)、D7(ArcticDB)
2. **数据导出**:写 `scripts/export_qlib.py`(ArcticDB → CSV → `dump_bin`);先导出日线 + 复权因子 + 涨跌停标记字段
3. **对账数据**:用 `chenditc/investment_data` 数据包对比复权价和交易日(见 D10 第五部分)
4. **跑通基准**:Alpha158 + LightGBM + `TopkDropoutStrategy`,确认流程能跑、指标合理
5. **接入自定义部分**:字段(资金流等)→ 处理器(P5 规则)→ PIT 财务 → 自定义算子
6. **一致性对账**:同一策略在 qlib 和自研引擎各跑一次,差异可解释后才算接入完成
7. **接到平台**:研究结果(预测、因子评估、回测记录)写回项目对应的表;前端 `/qlib`(现在跳转到因子实验室 ML 标签)展示 qlib 实验记录
8. **日常运行**:盘后增量导出纳入调度(只在主机),训练按需手动触发

**四、需要注意的事项**
- **口径一致是第一位**:日历、复权方式、成交价(次日开盘)、费率、涨跌停规则,qlib 和自研引擎必须相同,否则研究结论不能指导模拟盘
- **防泄露**:财务按公告日;处理器只用训练段拟合;标签用未来收益时注意对齐;检验段锁定
- **股票池**:用历史成分并包含退市股
- **qlib 不负责的东西**:模拟盘、待执行单、下单都留在自研执行层
- **多设备**:`.bin` 数据和 MLflow 记录只在主机生成;开发机通过快照拿
- **依赖冲突**:qlib 对 numpy / pandas 版本敏感,升级其他包前先确认不破坏 qlib;RD-Agent 用自己固定版本的 qlib(独立 conda 环境),不与项目环境混用
- **存储**:全市场 10 年 `.bin` 约数 GB,放 `data/qlib_data/`,不进 git

### D13 · 因子拥挤度监控
> 参考:公众号"杰智远AI投研"《因子拥挤度:怎么度量,怎么应对》(2026-10-20)。
> 核心原则:**拥挤度是尾部风险指标,不是择时信号**。高拥挤之后平均收益未必为负,但下尾明显变厚;它回答"出事时有多惨",不回答"什么时候出事"。放进风险管理,不用来预测涨跌。

**一、度量方法与数据可行性**
| 方法 | 算法 | 现有数据 | 可行性 |
|---|---|---|---|
| 估值价差 | 因子多头组合 vs 空头组合的估值(PE / PB)差,看其在历史中的分位 | `valuation_snapshots` | ✅ 可算;**依赖 P1 补历史**才能看历史分位 |
| 成交量占比 / 换手 | 多头组合成交额占全市场比例、换手率是否异常升高 | `stock_daily_quotes` | ✅ 可算;同样依赖 P1 |
| 因子收益波动与相关性 | 因子日收益的滚动波动率;与原本不相关因子的滚动相关性是否上升 | 需先算因子收益序列(D3 本来要做) | ✅ 可算 |
| 持仓重叠度 | 不同组合持有同一批股票的程度 | 仅 `etf_holdings`(350 只 ETF)、北向十大成交股 | ⚠️ 不完整;可补 Tushare 公募基金持仓(季度披露,有滞后) |
- 多个指标标准化后合成一个拥挤度综合分,同时保留各分项

**二、接入位置**
1. **D3 因子专业化**:每个因子在 IC / 收益之外增加拥挤度指标,进入因子评估报告
2. **D10 LLM 挖因子**:新因子计算与市场热门因子的持仓重叠和相关性;高度重叠的标记"拥挤风险"(参考 AlphaAgent、QuantaAlpha 的防拥挤设计)
3. **模拟盘风控**:策略依赖的因子拥挤度高时,**逐步降低权重**(不清仓),或在页面提示;拥挤度高时禁止加仓 / 杠杆类操作
4. **风险预算**:拥挤度高的因子分配更小的风险预算
5. **压力测试**:估算组合平仓所需天数和冲击成本;情景设为"相关性上升 + 成交难度上升同时发生"
6. **D4 学习**:本文主题适合放进学习中心

**三、注意**
- 不做择时信号,不根据拥挤度预测涨跌
- 历史分位需要足够长的样本(依赖 P1);样本不足时只展示数值,不给分位判断
- 持仓数据有披露滞后,重叠度只能作为慢变量参考
- 关联:D3、D10、D5(模拟盘)、P1、P5
- 状态:⏳ 未开始

### D14 · 组合构建与风险管理层(新增)
> 参考框架:Paleologo《Advanced Portfolio Management: A Quant's Guide for Fundamental Investors》(Wiley, 2021)。只借鉴框架和思路,不摘录原文。
> 定位:补上"找到信号"和"模拟盘 / 实盘"之间缺失的一层——**有了 alpha 之后,怎么定仓位、控风险、做归因、止损**。书从美股多空对冲基金视角写,A 股做空受限、个人账户无杠杆,对冲与杠杆部分需打折扣。

**一、要做的事项**
1. **多因子风险模型**(书第 3~4 章)
   - 风格因子:市值、价值、动量、波动率、流动性、成长、质量等;行业因子用申万一级
   - 每日截面回归得到因子收益和个股特质收益;估计因子协方差矩阵和特质方差
   - 产出:每只股票的因子暴露、组合的事前风险(总风险 = 因子风险 + 特质风险)
   - 可借鉴 qlib 的风险模型模块(D12 研究层),数据依赖 P1 补历史
2. **风险分解**(第 3 章):组合风险拆到各因子和个股,显示"这个组合的风险有多少来自小盘暴露 / 某个行业"
3. **按风险定仓位**(第 6 章):替代现在的等权 / 简单加权
   - 候选方法:按预期收益 ÷ 风险比例分配、风险平价、波动率目标
   - 对比测试:等权 vs 按风险定仓,在同一策略上比较夏普和回撤
4. **因子暴露控制**(第 7 章):限制组合在行业、市值、风格上的暴露(例如行业偏离基准不超过 X%、市值暴露在一定区间);A 股无法做空时,通过选股和权重约束实现,不靠空头对冲;必要时可用股指期货对冲 beta(依赖 D9 期货数据)
5. **业绩归因**(第 8 章,优先级高):每个组合的收益拆成 市场 beta + 风格因子 + 行业 + 个股特质(真 alpha)
   - 现有 `portfolioAttribution` 接口升级
   - 判断标准:收益主要来自特质部分的策略才算有选股能力;主要来自风格暴露的,风格切换时会亏
   - 与"策略合适就用于实盘"的定位直接相关:**进入实盘前必须看归因**
6. **系统性止损规则**(第 9 章):现在只有海龟策略有止损;评估在个股层和组合层引入止损的成本与收益(止损会切掉尾部,也会在反弹前卖出),回测对比后再决定
7. **事件交易**(第 8 章):财报发布等事件前后的仓位处理(你已有财报日历、业绩预告、盈余惊喜因子)
8. **组合优化**(附录):均值方差优化、带约束的优化(仓位上限、换手限制、暴露约束);v1 用简单规则,v2 再上优化器
9. **杠杆**(第 10 章):个人账户不涉及,**暂不做**

### D15 · 因子准入与体检流程(新增,来源:公众号"程飞"《因子选择:7 个方向胜过 N 个因子》)
> 文章结论:A 股 20 个量价因子(2011-04 ~ 2026-06,186 个截面)互相回归取残差后,IC 总量只剩 18.3%,有 11 对相关系数 > 0.7;直接逐个等权相加最好 IR 0.807,还不如最强单因子 0.809;先正交再加,7 个方向 IR 1.039(+28.4%),超过 7 个回落。**选因子是减法:先问"跟谁重复",再问"有多强"。**
> 文章口径局限(参考时注意):价格不复权(用涨跌幅重建)、用成交额代理市值、正交结果依赖固定顺序(Gram-Schmidt)、分层净值未扣成本、作者自述只放了好看的结果。数字不直接照搬,方法照搬,用我们自己的数据重算。

**一、准入顺序(作为 D3 / D10 共用的因子准入流程)**
1. **合理性闸门(项目统一的"可疑结果"阈值)**:日频单因子 |IC| > 0.15 标黄、> 0.3 标红;组合或策略回测夏普 > 3 标黄;分层单调得像画出来的、净值过于平滑也标黄。标黄要人工复核,标红先查代码(文中真实案例:取数函数 `t+k` 写成 `t-k`,用未来数据算出 IC -0.80)。配套"未来函数单测"(安慰剂检验:打乱因子值 / 打乱日期后重算,IC 应归零)
2. **随机因子对照**:每次体检生成 100 个随机因子(遮罩与真实因子一致),给出随机 IC 的标准差和真实因子的倍数。t 值不作主判据(大样本下 IC 0.02 也能 t>5);需要时只看 **Newey-West 修正后的 t 值**,作辅助参考;t 值在 2.0–2.5 的标"边缘",须跨版本 / 跨区间复核(D16 第 2、11 条)
3. **先查重复(项目统一的相关性准入阈值)**:新因子与已有因子的截面 Spearman 相关矩阵(按期平均),取库内最大 |ρ|:
   - < 0.5:直接进入下一步
   - 0.5–0.7:必须在第 4 步证明残差 IC 有增益才准入
   - > 0.7:视为同一因子,只能走"替换"(强度明显更好时替换旧因子,参考 D10 第 6 条 FactorMiner 替换规则,阈值按日频重新校准)
   - > 0.85:直接二选一
   - 画"最大相关 × 强度"散点,优先收"不强但不重复"的
4. **剔除后再看增益**:对其余因子做截面回归取残差,看残差 IC / 残差 IR;残差几乎为零的因子不准入(信息已被别的因子覆盖)
5. **最后才是权重**:等权 / IC 加权 / ICIR 加权 / 最优化差距小,权重调优优先级最低

**二、因子体检报告标准项(接 D12 qlib 研究层的 SigAnaRecord 扩展)**
- IC 均值、ICIR、每期 IC 箱线图、IC 时序与逐年热力图
- **IC 衰减曲线**:5/10/20/60 日;60 日/20 日比值决定该因子的调仓频率(不同因子不强行同一频率)
- 十分组分层 + **单调性得分**(≥0.8 好,0.5~0.8 勉强,<0.3 淘汰)
- 正交残差 IC 及保留比例(分母接近零时只看绝对值)
- 涨市 / 跌市分拆 IC;大盘 / 小盘分拆 IC
- IC 一阶自相关(文中全部接近零 → 基于历史表现的因子轮动缺乏统计基础,轮动类方案需先过这项检验)
- 头部组换手率;可交易性提示(非流动性类因子强度部分来自"买不到")
- 样本内外切分保留率;高保留率同时提示拥挤风险(接 D13)
- 六维雷达 / 归一化总表:强度、稳定性、单调性、跨年稳定、剔除后留存、低换手

**三、对现有系统的直接影响**

### D16 · 2026-11-17 研读补充(21 篇公众号文章 + 其中引用的论文原文)
> 来源:21 篇公众号文章(Newey-West、反过拟合三件套、因子检验三件套、Gram-Schmidt/Löwdin 正交化、多因子排序避坑、残余现金收益 RCE、广发 L2 撤单、图网络、QBX、方正 LLM+遗传规划、HRT 演讲、Fama-French 版本、指增/中性/CTA、量化数据三类、MACD 导数、波动率、对数正态、ARIMA+LSTM+Prophet 等)及原论文:QBX(arXiv 2610.41689,读全文)、Noisy Factors(Review of Finance 2026,读 2024 修订稿全文)、Navigating the Alpha Jungle(arXiv 2505.11122,AAAI 2026)、LLEGO(ICLR 2025)、LLM-GP、Milano《Beyond EVA》(JACF 2019,仅摘要)、Cohen-Frazzini 2008、Ahern、FinDKG、Moskowitz-Ooi-Pedersen 2012、Grinold 1989、Newey-West 1987、Deflated Sharpe 2014。
> 下面按"并入哪一项"组织;各条在对应事项实施时一并处理。

**1. ⚠️ 代码问题 → 并入 P2**
- [backend/services/factor_orthogonal.py](../backend/services/factor_orthogonal.py) 文件说明写"对称正交化 (Löwdin)",实际实现的是**经典 Gram-Schmidt**:结果依赖 `factor_ids` 传入顺序、数值不稳定、纯 Python 三重循环很慢。已注册的"正交因子"哪个保留全部信息取决于传参顺序
- 改法:真 Löwdin 用 `numpy.linalg.eigh` 求 `C^(-1/2)`;需要先后顺序时用修正 Gram-Schmidt / QR 并**显式传顺序**(风格因子 Beta/市值/价值在前,Alpha 按 IC 降序);输出 VIF 报告(<5 安全,5–10 需正则,≥10 必须正交);与 `factor_neutralize.py` 统一接口

**2. 统计检验 → 补进 D15**
- **Newey-West(HAC)t 值**:20 日前瞻收益的日度 IC,`maxlags=19`(statsmodels `cov_type='HAC'`);D15"不看 t 值"改为"只看 NW 修正后的 t 值,且只作辅助"
- **安慰剂检验**:打乱因子值、打乱日期两种做法(并入 D15 的"未来函数单测")
- **Walk-forward**:用 qlib RollingGen(接 D12)
- **IC 为正比例**(≥60% 视为稳定)、**分年度超额**(避免"靠两年撑起来")加进体检报告;检验要扣交易成本
- **试验账本**:每测一个候选因子记一次(手工研究也记),作为多重检验的分母
- **Deflated Sharpe 只作参考**:QBX 作者发现它在**标签重叠时偏乐观**,主判据用联合最大值 bootstrap(White Reality Check / Hansen SPA)
- **5 个低频基线因子**(小市值 `-ln(市值)`、21 日反转、12-1 动量、3 个月换手、EP 行业内比较且亏损股单列):新因子须先证明相对这 5 个有增量

**3. LLM 挖因子 → 补进 D10**
- **编译期检查**(QBX):`factor_expression.py` 升级为"类型检查 + 时间偏移检查"——算子声明输入类型和时间偏移 φ(当期 0、过去负、未来正;合并取最大;滞后减、窗口不变),任何节点 φ>0 直接拒绝,不进回测。论文:有效率 26.8% → 97.7%,植入的 6 个泄露因子训练/测试切分 0/6 发现、静态检查 6/6 拦下
- **边界写清**:编译期只挡表达式里的未来引用,**挡不住**财务修订、事后成分股、公告时点等数据层问题(仍靠 P5 和公告日对齐);"零违规"≠"零泄露"
- **经济量纲警告**(只警告不拦):存量与流量混算、`log(市值)` 依赖单位、截面排名缺点时股票池
- **规范化哈希**:代数规范化后取哈希,用于去重 + 试验账本键(去重和计数必须用同一个键,否则账本和实际计算对不上);论文:逐字去重对准入后的候选无效,规范化改写再去 13.8%,结构不同但值相同的还有 27.9%(需评估后按值去重,接 D15 相关性准入)
- **节点级缓存**:子表达式结果按哈希缓存,变体只重算下游(论文 7.5×,零误差);缓存键要含数据版本、股票池、区间
- **评分方式**(Alpha Jungle):有效性、稳定性、换手、多样性、过拟合风险五维,每维按"在已入库因子里的百分位"打分,门槛随库变强自动抬高;过拟合风险由 LLM 读公式和精炼历史判断;入库门槛 IC>0.02
- **针对短板精炼**:按"满分减当前分"做 softmax 选维度;LLM 先写文字改进建议,再转成公式;允许非叶子节点继续扩展(虚拟扩展动作)。消融:IC 0.0409(只看有效性)→ 0.0549(五维 + 频繁子树回避);加换手维度 IC 略降但超额和 IR 上升
- **频繁子树回避**:统计已入库因子里叶子都是原始字段的高频子树,提示 LLM 避开,成本低、实测有效
- **泄露基线**:每次实验同时跑"直接让 LLM 写高表现因子"和"随机公式"两组对照(论文:RankIC 0.022–0.024 / 0.018 / 方法 0.071),补充 D10 第四(补)节的时间穿越检验
- **混合搜索(v2)**:LLM 只做种子、语义变异、精英修剪(方正 TEDE 思路;LLEGO 的适应度引导交叉 f* = f_max + α(f_max−f_min)、多样性引导变异按负对数概率和温度 τ 抽样),大量局部变体由 gplearn / 编译器在本地生成。QBX:准入一次 57 微秒 vs LLM 一次 1.45 秒;LLM 广度 + 本地深度混合 RankICIR +0.036~0.038(3 个种子,探索性);纯本地搜索会坍缩(有效广度 1.0–1.9),必须配多样性约束

- 定义:GCE = 核心经营 EBIT + 折旧 − 现金所得税(按递延税调整)+ 研发;GOA = 固定资产原值 + 在建工程 + 经营营运资本 + 研发资本化存量(年折旧 20%)+ 商誉 + 无形资产 + 开发支出;RCE = GCE − 2.5% × 平均 GOA(季度)
- 证据等级:概念出自推广方 Milano / Fortuna Advisors 的自证(摘要称 20 个行业对 TSR 解释力优于 EVA,无数字),A 股证据只有一篇券商回测 → **先用自己的数据复现**再考虑入库
- 数据缺口:`financial_reports` 只有 29 个核心字段,缺折旧、研发、递延所得税资产/负债、固定资产、在建工程、商誉、无形资产、开发支出、经营性流动资产/负债明细 → P1 财务加深时改拉 Tushare 利润表 / 资产负债表 / 现金流量表**全字段**,保留公告日

**7. 风险层 → 补进 D14**
- 波动率定仓:保持"仓位 × 波动率"大致稳定(第 3 条按风险定仓的一种)
- 主动管理基本定律 IR ≈ TC × IC × √BR:"独立判断次数"与 D15 有效独立因子数统一呈现;**转移系数 TC** 衡量 A 股不能做空等约束吃掉多少信号,放进风险报告

- **固定代码的现成参照 → 补进第 4 条和 D15**:Open Source Asset Pricing(Chen & Zimmermann,Critical Finance Review 2022;Noisy Factors 用它做异象样本)公开了逐个复现 300 多个截面预测因子的代码和数据,当前版本(2.0.0)维护 195 个有多空收益的因子。可作为 D3 因子定义的对照来源,以及"代码公开、方法固定、版本归档"的范本(美股部分可直接对照 D1)
- **因子的可交易替代 → 补进 D14**:Noisy Factors 建议参考 Berk & van Binsbergen(2015)用可交易的指数基金 / ETF 做基准。我们评估组合时,基准优先用可交易指数或 ETF 收益,不用自己构造的多空因子收益作为唯一标尺
- **边缘显著要谨慎 → 补进 D15**:Noisy Factors 中 t 值在 2.0–2.5 的异象约 28% 换数据版本就不显著(呼应 Harvey & Liu 2020 关于错误发现和漏掉发现的讨论)。D15 准入时,t 值落在这个区间的因子标"边缘",必须做跨版本 / 跨区间复核
- **L2 撤单因子的数据前提 → 补进第 9 条**:广发的因子基于逐笔委托(含撤单的订单号、毫秒时间戳、部分撤单),我们的 `stock_moneyflow_l2_daily` 是按单子大小汇总的日级资金流,不含撤单信息,无法复现。若将来购买逐笔数据,先只测与 Barra 风格相关性 <30% 的时间结构类和快慢撤单差异类因子,再按 D15 准入
- **"量化方法"一文**:内容基本是 Maarten Grootendorst《A Visual Guide to Quantization》(2024)的中文编译(未注明出处),讲大模型的权重/激活 INT8 量化,与量化投资无关;仅在 D10 本机跑开源模型时作背景知识(权重量化用于降低显存,激活量化更难)

### D17 · 文字策略描述 → 量化策略(**可选的额外功能**,2026-11-17 记录)
> 定位:额外可加入的功能,**不在重构主线内,未排期**;等 D10 / D12 底座就绪后再决定是否做。

- **核心原则**:LLM 只做"翻译",不直接写回测代码。文字 → 结构化策略描述(JSON/YAML)→ 编译检查 → qlib 表达式(统一口径见 D12 第一部分第 5 条)→ qlib / 自研引擎执行。原因:文字描述必有歧义,LLM 会擅自补全;自由生成的代码容易用到未来数据(QBX:自由文本只有 26.8% 能跑通)
- **流程**:① LLM 翻译,并把说不清的地方列成问题 → ② 用户确认或补充 → ③ 编译检查(字段 / 算子是否存在、类型、未来数据,复用 D10 / D16 第 3 条的检查器)→ ④ 转成 qlib 表达式或因子回测 → ⑤ 报告:回测结果 + D15 体检 + 本次补了哪些假设
- **结构化描述五块**:选股池(范围、剔除 ST / 次新)、信号(因子表达式或条件组合)、组合(持股数、权重方式、行业上限)、调仓(频率、成交价)、风控(止损、仓位上限)
- **示例**:"选低估值、近期放量突破的中小盘,每周调仓持 20 只" → 中证 1000;行业内 PB 后 30%;5 日均量 > 20 日均量 × 1.5 且收盘创 20 日新高;综合分前 20 等权,周五收盘调仓;附待确认问题(PB 还是 PE、放量倍数、突破 20 日还是 60 日)
- **能力边界**:
  - 能做:因子类、规则类策略(多因子、均线 / 突破、轮动、红利防御)
  - 看数据:涉及新闻、政策、研报的,只能从有数据起回测(见 P2)
  - 做不到:盘中 / 高频 / 依赖盘口(无逐笔数据);过于模糊的描述只能翻成用户确认过的具体指标
  - 翻译后的策略回测好看 ≠ 原想法有效,必须附假设清单并过 D15
- **现状差距**(2026-11-17 查代码):`llm_client.py` 可用;`factor_expression.py` 只有 7 个函数(Ref/Mean/Std/Delta/Rank/Abs/Log)、逐只循环、无类型和未来数据检查;`backtest_engine.py` 用 `if/elif` 写死策略,无法执行任意结构化描述(最需要改)
- **分版本**(如决定做):
  - v1:选股池 + 因子打分 + 前 N 等权 + 固定周期调仓,翻成 qlib 表达式回测,附待确认问题和假设清单
  - v2:加规则类信号(条件组合、止损);自研执行层改为接收结构化描述,替换 `if/elif`;接 D15 体检,一键加入模拟盘(D5)
  - v3:多轮对话修改策略,每版记版本号并写入试验账本
- **依赖**:D12(qlib 研究层)、D10 / D16 第 3 条(编译检查器,可共用)、D15(体检)、D5(模拟盘)
- 状态:💡 可选,未排期

### D18 · 统一事件日历(多时区 + 交易日 + 财报 + 宏观 + 央行会议)(新增,2026-11-18)

**一、时区规则(先定死,再接数据)**
- 存储:每个事件存 **UTC 时间 + 来源时区(IANA 名,如 `Asia/Shanghai`、`America/New_York`、`Europe/Frankfurt`)+ 来源当地时间原文**;只有日期没有时刻的事件(如财报预约日)存"来源市场的日期 + 全天",**不做时区换算**,避免跨天错位
- 展示:按**系统当前时区**显示(前端取浏览器时区,后端取机器时区,可在设置里改),同时可切换显示"事件所在市场的当地时间"

- 交易日 / 交易时段:A 股(P1 补到 2015)、美股(NYSE 休市和半日市)、港股(如以后需要);推荐用开源交易所日历库(如 `exchange_calendars`)生成,与 Tushare 交易日历对账
- 两台机器(开发机 / 主机)时区可能不同:所有调度和"今天"的判断都按市场时区算,不依赖机器本地时区

### P5 · 统一研究数据清洗流水线(D3 的基础)
所有因子计算、回测、ML 走同一套规则,避免各模块口径不一致:
- **复权**:收益用复权价;成交和涨跌停判断用原始价
- **停牌**:停牌日不算收益、不可交易,不能用前值填充当作正常交易(用 `is_suspended`)
- **涨跌停**:一字涨停不可买、跌停不可卖;回算因子时也要标记
- **新股**:上市前 N 天(常用 60 天)排除,做成通用开关
- **ST / 退市整理**:按**当时的**状态排除(Tushare `namechange` 获取历史 ST)
- **去极值**:MAD(中位数 ± 3~5 倍 MAD)或分位数截尾(1%/99%);可复用 `data_quality_alerts` 异常检测
- **标准化**:每日截面 z-score 或排名
- **中性化**:对行业和市值回归取残差;现有 14 个中性化因子统一到这套流程
- **缺失值**:真缺失剔除;财务按最近一期向前填充并限制最长期限;不用均值填充(可复用 `test_ml_impute.py` 的规则)
- **时点对齐**:财务按公告日;行业分类、ST 状态、成分股都用历史版本(同 P2)
- **幸存者偏差**:股票池包含退市股(同 P1、P3)

### P13 · 回测正确性与性能(新增,2026-11-19)
- 来源:回测页三个接口(`/api/backtest/scan`、`/rolling`、`/walk-forward`)在 P4 页面验证时都超过 90 秒,做了性能分析,详见 [`回测性能分析-20261119.md`](回测性能分析-20261119.md)
- 结论:慢的原因是重复读库和附带的健康检查，不在语言。单次回测 8.3 秒里，读评分 4.4 秒、读行情约 2.5 秒，模拟本身约 1 秒。**不改 Rust**,也不使用闭源的 `qars3`
- **正确性问题(优先)**:
  1. **滚动回测不滚动**:8 个窗口全是同一区间(开发机实测都是 `2026-06-29 ~ 10-26`)。原因是每次回测都以今天为终点，只改回看天数，再截取"最后 80 天"。页面上的胜率和窗口夏普不能当作稳定性证据
  2. **walk-forward 没有样本外**:测试窗(6/29–10/26)完整包含训练窗(7/27–10/26),显示的"测试收益"实为样本内结果，违反定位里"研究结论必须样本外"
  3. `/api/strategy/rolling-backtest` 调用同一个函数，同样受影响
- **性能问题**:
  1. scan / rolling / walk-forward 循环调用 `run_backtest()` 8–13 次，每次都重新读全部行情和评分
  2. 每个回测结果都经 `attach_meta()` 附带健康检查(含 4 次因子 IC 分析)。缓存为空时同步算 116 秒;启动预热函数 `warm_beta_health()` 无人调用;缓存过期后在后台重跑约 100 秒重查询
  3. 接口写成 `async def` 却直接调用同步重计算，运行期间(40–70 秒)整个后端的其他请求都在排队
  4. `comprehensive_scores` 每行很宽，查询只要一个分数却读整行，要 4.3 秒(只读索引列 0.1 秒);`(stock_id, calc_date)` 上有 4 个重复索引
- 方案(按优先级):
  1. **修正窗口逻辑**:rolling 按时间分段;walk-forward 训练窗在前、测试窗在后，互不重叠。部署稳定后**尽快单独修**,不等 D11
  2. 健康检查与回测脱钩：回测只附带数据截至日期;健康检查由调度任务写入文件或表，后端只读;去掉健康检查里的 IC 分析(小改动，可单独做)
  3. 三个接口改为普通 `def`(FastAPI 放线程池)或后台任务 + 轮询(小改动)
  4. 数据只读一次:`run_backtest` 拆成"读数据"和"模拟",多组参数共用一份内存数据(scan 预计 40 秒降到约 15 秒)。**并入 D11**:研究层改用 qlib 时一起做
  5. 评分表加覆盖索引(如 `(calc_date, stock_id, composite_v5)`),删 3 个重复索引。走迁移;若 D7 ArcticDB 很快接手评分数据，可跳过
  6. 模拟循环向量化(polars/numpy),只在 1–5 做完后它成为瓶颈时才做
- 验收：滚动回测各窗口区间不同;walk-forward 的测试区间全部晚于训练区间;scan / rolling / walk-forward 在主机上 30 秒内返回;运行期间其他页面响应不变慢
- 状态:⏳ 未开始(第 1–3 条在 2026-11-20 主机部署稳定后单独开分支做;第 4–5 条随 D11 / D7)
