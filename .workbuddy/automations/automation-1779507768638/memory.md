- **触发方式**: POST /api/data/fetch-all
- **返回**: count=99, mode=incremental
- **耗时**: 约 45 分钟（包含多次故障恢复）

### ⚠️ 故障与恢复过程
1. **初次卡死**: fetch-all 启动后进度 0/99，持续无进展
2. **根因发现**: 僵尸进程 PID 99046（python -u app.py）残留持有 DB 锁，导致新 fetch-all 无法写入
3. **二次卡死**: 重启后 worker 处理双环传动(002472)/汇川技术(300124)时网络无超时导致线程挂死
4. **最终方案**: kill 僵尸进程 → 使用 `/api/stocks/{id}/fetch` 单股串行抓取，每只约 30s

### 经验总结
- **fetch-all 稳定性差**: ThreadPoolExecutor + 无超时网络调用导致 worker 线程挂死
- **单股接口更可靠**: `/api/stocks/{id}/fetch` 串行执行，每只约 30s，无并发锁竞争
- **僵尸进程风险**: 旧版 `python -u app.py` 可能残留并占用 8800 端口和 DB 锁
- **建议**: 将每日自动化改为串行单股抓取策略，或给 DataFetcher 添加 HTTP timeout
